# スマホの翻訳スクリプト A（自分の声 → ペットの上の文字）設計書

日付: 2026-11-16
もとの資料: 「VRChat 英語学習 翻訳ツール PRD」（2026-11-15）の「PRD A」
関係する設計書: `2026-11-16-translator-pet-design.md`（アバター側。完成済み）

## 目的

VRChat で英語を練習するために、自分が話した言葉をその場で訳して、アバターのペットの上の文字（KAT）に出す。日本語で話せば英語が、英語で話せば日本語が出る。周りのプレイヤーにも見える。

- 英語で言いたいことを日本語で話して、英文を見て学ぶ
- 自分の英語がどう伝わったかを、日本語訳で確かめる
- あとで復習できるように、翻訳を記録する

あとで BOOTH で配ることを考えて、初めての人でも入れられる形にする。

## 全体の中での位置づけ

PRD の作業順（利用者と合意済み）:

1. アバター側（完成）
2. **スマホのスクリプト A（この設計書）**
3. ツール B（相手の声をスマホに表示）
4. ローカル AI 版

## やること

- スマホ（AQUOS R9、Termux）で、アバターのトグルがオンの間だけ声を聞き、話し終わりを自動で見つけて翻訳する
- Gemini で、文字起こし、言語判定、翻訳を1回で行う
- 訳を KAT の形式で PC の VRChat に送り、ペットの上に出す
- 翻訳中は「...」を出す
- 原文も出すかを設定で切り替える
- 128 文字に収まらないときは、ページに分けて順に出す
- 翻訳を日時つきで記録する
- 予備として、VRChat 標準のチャットボックスにも出せる
- PC で動かす中継スクリプト（PC と スマホの間で OSC を受け渡す）

## やらないこと（この段階では）

- ローカル AI（whisper.cpp、llama.cpp）と、AI の切り替え。アバターの「ローカルAI」トグルは受け取るが、今は何もしない（第4段階で使う）
- ツール B（相手の声）と、スマホ内の Web ページ
- OSCQuery への対応（配布の前に足す）
- Termux:Widget のボタンと、`.exe` 化
- 説明書（BOOTH 用）。この段階では、自分用のセットアップ手順を README に書くだけ

## 避けたいこと

- エラーでプログラムが止まり、遊んでいる最中にスマホを触らないといけなくなること
- API キーがコードやログに残ること
- 相手の声を録音・送信すること（このスクリプトはトグルがオンの間の自分のマイクだけ）
- pip での追加インストールが必要になること

## 前提

- PC: Windows、VRChat デスクトップモード、OSC を有効にしてある。Python 3 が入っている
- スマホ: AQUOS R9、F-Droid 版の Termux と Termux:API
- PC とスマホが同じ Wi-Fi
- Gemini の API キー（Google AI Studio で作る）。環境変数 `GEMINI_API_KEY` で渡す
- アバター側: `TranslatorActive`（Bool、同期）、`TranslatorLocalAI`（Bool）、KAT（同期設定 8）

## 作り方の候補と選んだもの

スマホがトグルのオン・オフを知る方法:

| 案 | 内容 | 良い点 | 悪い点 |
|---|---|---|---|
| 1 | VRChat の起動オプション `--osc=9000:<スマホIP>:9001` で、送り先をスマホにする | PC 側にプログラムが要らない | ほかの OSC アプリが使えなくなる。スマホの IP が変わると書き直し |
| **2（採用）** | PC で中継スクリプトを動かす | ほかの OSC アプリと共存できる（OSCQuery を足せば完全に）。ファイアウォールの対策も兼ねる。IP の設定が少ない | 遊ぶ前に PC でスクリプトを起動する |

利用者が案2を選んだ。理由は、BOOTH で配るとき、ほかの OSC ツールを壊さず、設定でつまずく人が少ないため。PC の負荷はほぼない（転送だけ。CPU 1% 未満）。

## スマホ側の動き

### 状態

| 状態 | 何をしているか |
|---|---|
| 待機 | トグルがオフ。マイクは止めている |
| 聞いている | トグルがオン。音の大きさを見ている |
| 録音中 | 話し始めを見つけた。音をためている |
| 翻訳中 | Gemini に問い合わせている。その間も次の声は聞いている |

- トグルがオンになったらマイクを開き、オフになったら閉じる
- 翻訳は別のスレッドで1件ずつ順に行う。翻訳中に話し始めた声も録音し、順番待ちにする
- 録音や翻訳の途中でオフになったら、録音中の声は捨てる。翻訳中のものは最後まで訳して記録するが、表示はしない

### マイクと声の区切り

- マイク: `parec --raw --format=s16le --rate=16000 --channels=1` を子プロセスで起動し、標準出力から読む（PulseAudio の `module-sles-source` を使う）
- 30 ミリ秒ごとに音の大きさ（RMS）を計算する
- 周りの雑音の大きさを、静かなときの値からゆっくり追いかけて覚える。雑音より一定以上大きい音を「声」とみなす
- 話し始め: 声が 0.15 秒続いたら録音を始める。話し始めが欠けないよう、直前 0.3 秒もさかのぼって入れる
- 話し終わり: 無音が 0.8 秒続いたら録音を止める
- 1回は最大 60 秒。超えたらそこで区切る
- 0.5 秒より短い録音（咳や物音）は捨てる
- 録音は WAV（16 kHz、モノラル、16 ビット）にする。Python 標準の `wave` で作れる
- しきい値と時間は `settings.ini` で変えられる

**AQUOS R9 で `parec` が使えるかは未確認。** 最初に `mic_check.py`（音の大きさを棒グラフで表示するだけ）で確かめる。使えないときは、`termux-microphone-record` で 1 回ずつ録音し、ffmpeg で音の大きさを読む方法に切り替える。その場合はこの節を書き直す。

### Gemini への問い合わせ

- `POST https://generativelanguage.googleapis.com/v1beta/models/{MODEL}:generateContent`。キーはヘッダー `x-goog-api-key` で渡す（URL に入れない）
- 音声は `inline_data`（`audio/wav`、Base64）で送る
- 返答は JSON に固定する（`responseMimeType: application/json` と `responseSchema`）。項目:

| 項目 | 内容 |
|---|---|
| `lang` | `ja`、`en`、`none`（話し声がない、聞き取れない） |
| `original` | 文字起こし |
| `translation` | 反対の言語への訳。くだけた自然な言い回し。できれば 120 文字以内 |
| `kana` | 日本語の側（`ja` なら `original`、`en` なら `translation`）を、ひらがなとカタカナだけで書いたもの。漢字を使わない |

- `lang` が `none` のときは、何も表示せず、記録もしない
- タイムアウトは 20 秒。失敗したら 1 回だけやり直す
- モデルは `gemini-flash-latest`（設定で変えられる）
- `GEMINI_API_KEY` がないときは、起動時にエラーを出して終わる

### 表示

KAT は 32 文字 × 4 行。改行がないので、行の頭をそろえたいときは空白で埋める。

| 話した言語 | 1行目から | 原文を出すとき（`SHOW_ORIGINAL`）、次の行の頭から |
|---|---|---|
| 日本語 | 英訳 | `(` + かなの原文 + `)` |
| 英語 | かなの日本語訳 | `(` + 英語の原文 + `)` |

- 翻訳中は `...` を出す
- 128 文字に収まらないときは、128 文字ずつのページに分け、1 ページを 5 秒見せてから次へ進む。最後のページはそのまま残す
- 表示中は、同じ文を数秒おきに送り直す（あとから来た人や、取りこぼした人にも全文が届くように）。次の訳が来たら止める
- 表示は次に話すまで残す。トグルをオフにすると、アバター側が消す
- チャットボックス（予備）: `DISPLAY` が `chatbox` か `both` のとき、漢字まじりの文を `/chatbox/input`（文字列、`True`、`False`）で送る。144 文字まで。翻訳中は `/chatbox/typing` を `True` にする
- 送り先は PC の中継スクリプト（`PC_IP:9002`）

### トグルの状態の受信

- スマホの 9001 番で OSC を受け取る
- `/avatar/parameters/TranslatorActive`（Bool）で、聞く・止めるを切り替える
- `/avatar/parameters/TranslatorLocalAI` は記録だけする（今は使わない）
- 起動直後は「オフ」とみなす。中継スクリプトがスマホを見つけるまでは値が届かない
- スマホは 5 秒ごとに `/translator/hello` を `PC_IP:9002` に送り、中継スクリプトに自分の居場所を知らせる

### 記録

- `~/vrc_translation_log.tsv` に 1 行ずつ追記する: 日時、言語、原文、訳、使った AI
- タブと改行は空白に置き換える
- API キーと音声は記録しない

### 設定（`settings.ini`）

| 名前 | 初期値 | 意味 |
|---|---|---|
| `PC_IP` | `192.168.1.10` | PC の IP アドレス |
| `RELAY_PORT` | `9002` | 中継スクリプトの受け口 |
| `LISTEN_PORT` | `9001` | スマホがトグルの状態を受け取る番号 |
| `MODEL` | `gemini-flash-latest` | Gemini のモデル |
| `SHOW_ORIGINAL` | `true` | 原文も出すか |
| `DISPLAY` | `kat` | `kat`、`chatbox`、`both` |
| `KAT_SYNC` | `8` | アバター側の KAT の同期設定と同じ値 |
| `LOG_FILE` | `~/vrc_translation_log.tsv` | 記録の場所 |
| 声の区切りの値 | 上の「マイクと声の区切り」の値 | しきい値、時間 |

### エラーのとき

- どのエラーでもプログラムは止めず、次の声を受け付ける
- 翻訳に失敗したら、ペットの上に `(error)` を 3 秒出して消す。理由は Termux の画面に出す
- マイクの子プロセスが落ちたら、2 秒待って開き直す
- PC に届かないとき（Wi-Fi が切れたなど）は、送信を捨てて続ける

## PC の中継スクリプト

- 9002 番で受信し、届いたものをすべて `127.0.0.1:9000`（VRChat）へ転送する。`/translator/hello` だけは転送せず、送り主のアドレスをスマホとして覚える
- 9001 番で VRChat の出力を受信し、`/avatar/parameters/TranslatorActive`、`/avatar/parameters/TranslatorLocalAI`、`/avatar/change` だけをスマホの 9001 番へ転送する。ほかは捨てる
- スマホをまだ知らないときは、転送しない
- アバターを変えたとき（`/avatar/change`）と、スマホを新しく見つけたときは、覚えている最新のトグルの値をスマホへ送り直す（VRChat は値が変わったときしか送らないため）
- 画面に、スマホを見つけたこと、トグルの変化、転送の数を1行ずつ出す
- `start_relay.bat` でダブルクリック起動できるようにする
- 初回の起動で Windows のファイアウォールの確認が出たら「プライベート ネットワーク」で許可する（README に書く）
- 9001 番をほかのアプリが使っているときは、起動時にその旨を出して終わる。OSCQuery に対応すれば共存できる（後の作業）

## テスト

Python 標準の `unittest`。PC で実行できるようにし、マイク、Gemini、ネットワークは偽物に置き換える。

- 声の区切り: 作った波形（無音 → 声 → 無音）で、始まりと終わり、さかのぼり、最大 60 秒、0.5 秒未満を捨てる、雑音への追従を確かめる
- Gemini: 送る JSON の形（キーがヘッダーにあり URL にない、音声が Base64、返答の形の指定）。返答の読み取り（`none`、壊れた JSON、HTTP エラー、やり直し 1 回）
- 表示: 行の頭そろえ、原文あり・なし、128 文字を超えるときのページ分け、チャットボックスの 144 文字の切り詰め
- OSC の受信: Bool、Int、Float、文字列の読み取り。壊れたパケットで止まらない
- 中継: ローカルのソケットで、転送する・しないの振り分け、hello でスマホを覚える、覚えた値の送り直し
- 記録: タブや改行が入っても 1 行になる。API キーが入らない
- 全体: トグルのオン → 声 → 翻訳 → 表示 → 記録の流れを、偽物の部品でつないで確かめる。翻訳中にオフにしたときに表示しないことも確かめる

## 作る人の目線で読み直したあとの追記（2026-11-16）

### 利用者の答え

- VRChat の音はヘッドホンで聞く。スマホのマイクが拾うのは自分の声だけ、という前提はこれで成り立つ。README の前提に「ヘッドホンで聞くこと（スピーカーだと相手の声も翻訳・記録されてしまう）」と書く
- スマホの画面はつけたままでも消してもよい。利用者は、画面を消しても録音できた記憶がある（おそらく Termux:API の録音コマンド）。`parec` で同じようにできるかは、`mic_check.py` で画面を消して確かめる
  - 画面を消すと `parec` の音が無音になるときは、まず「画面をつけたまま使う」で進める（利用者はどちらでもよいため）。そのうえで、録音コマンドを使う方法で画面を消しても使えるかを、あとで試す
  - セットアップで `termux-wake-lock` を実行し、省電力の設定で Termux を対象外にする

### 私（Claude）が決めたこと

- アバターを変えたとき（`/avatar/change`）は、スマホはトグルを「オフ」とみなし、新しい値が届くまで聞かない。中継スクリプトは、アバターを変えたあとに古いトグルの値を送り直さない（スマホを新しく見つけたときだけ、同じアバターのまま覚えている値を送る）
- 長い文: ページの 5 秒は、そのページを全部書き終えてから数える。送り直しは消去（ポインタ 255）をせず、同じ位置に上書きする
- Gemini の回数制限（HTTP 429）のときは、待つ時間を延ばしながら最大 3 回やり直す。それでもだめなら `(error)`。README に「話した声が Google に送られる。無料枠では Google のサービス改善に使われることがある」と書く
