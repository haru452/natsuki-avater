# 翻訳アプリ（スマホのローカル AI、相手の声、中国語）設計書

日付: 2026-11-17
関係する設計書:
- `2026-11-16-translator-pet-design.md`（アバター側。完成済み）
- `2026-11-16-phone-translator-a-design.md`（Termux 版のスクリプト A。この設計書で置き換える。OSC、KAT の表示、中継の決まりはそのまま引き継ぐ）

## 目的

VRChat で英語（と中国語）を使って話すために、AQUOS R9 の専用アプリで、

- **自分の声**を訳して、ペットの上の文字（KAT）かチャットボックスに出す（周りの人に見える）
- **相手の声**を訳して、スマホの画面に出す（自分だけが見る）

利用者がローカル AI を使いたい理由は 2 つ: **お金をかけたくない**、**早く返事がほしい**。普段はスマホの中だけで訳し、丁寧に訳したいときだけ Gemini に切り替える。

Termux の準備が面倒なので、アプリにする（利用者の希望）。あとで BOOTH で配ることも考える。

## やること

- Unity で作る Android アプリ（AQUOS R9 用）
- 自分の声: スマホのマイク → 声の区切り → 音声認識 → 翻訳 → PC の中継 → VRChat（KAT かチャットボックス）
- 相手の声: PC が VRChat の音だけを取り出す → Wi-Fi でスマホへ → 声の区切り → 音声認識 → 翻訳 → スマホの画面
- 言語:
  - 自分の声: 日本語 → 英語か中国語（アプリのスイッチで選ぶ）。英語、中国語で話したときは → 日本語
  - 相手の声: 英語、中国語 → 日本語（言語は自動で聞き分ける）。日本語の声は訳さずにそのまま出す
- AI の切り替え: アバターの「ローカルAI」トグル（`TranslatorLocalAI`）がオンならスマホの中の AI、オフなら Gemini
- Gemini の API キーを、アプリの画面に貼り付けて保存できる
- PC の中継を、ダブルクリックで起動する 1 つの `.exe` にする（OSC の中継と、VRChat の音の取り出し）
- 翻訳を記録する

## やらないこと

- iPhone、AQUOS R9 以外の機種での確認（動くように作るが、確かめるのは R9 だけ）
- 英語 ↔ 中国語の翻訳
- 相手の声の履歴（画面には最新の一言だけ）
- 相手の声を KAT やチャットボックスに出すこと（相手の声の訳は自分だけが見る）
- 話している人の聞き分け（誰が話したか）
- ストアでの配布。BOOTH 用の説明書（この段階では自分用の README だけ）
- OSCQuery への対応

## 避けたいこと

- 遊んでいる最中にアプリや PC の `.exe` が止まり、スマホや PC を触らないといけなくなること
- ローカル AI のときに、声や文がインターネットへ出ていくこと
- API キーが画面、ログ、記録に出ること
- PC で流している VRChat 以外の音（音楽、動画）を翻訳してしまうこと
- PC の負荷が増えて VRChat が重くなること

### 翻訳の AI（2026-11-17 に R9 で実測）

同じ 16 文（VRChat のくだけた会話、日 → 英 8、英 → 日 8）で比べた。

| | 1 文の時間 | 日本語 → 英語 | 英語 → 日本語 |
|---|---|---|---|
| ML Kit（Google の翻訳部品） | 0.02 秒 | 半分が不自然か誤訳 | かたい。ときどき誤訳 |
| Gemma 3 1B（Q4_K_M） | 約 1 秒 | 8 文とも自然 | 口調は自然。意味のない「やない」、取り違えあり |
| Gemma 3 4B（Q4_K_M） | 約 2〜4 秒 | 8 文とも自然 | ほぼ正しい。「もちろん、」を頭に付ける癖、1 回ローマ字を付け足した |

**利用者の決定: 自分の声は 1B、相手の声は 4B で訳す。** 自分の声は 1B で十分自然で速い。相手の声は意味を正しく取ることを優先する（画面で読むので 2〜3 秒は許せる）。どの向きをどちらで訳すかは、アプリの設定で変えられるようにする。

テストで分かったこと:
- PC から USB で動かしたとき、画面が消えていると 20 秒〜3 分かかることがあった。画面をつけておくと起きなかった
- 中国語の訳はまだ試していない（最初の作業で確かめる）
- 4B の癖は、指示文の書き方で直す（訳だけを返すように、例を添える）

## スマホのアプリ

### 画面

使っているあいだは画面をつけたままにする（スリープしない）。Unity は画面が消えると止まり、R9 の省電力で AI も遅くなるため。

メイン画面（相手の声）:

```
┌───────────────────────────┐
│ ● 中継: つながった  🎤 自分: 聞いている │  ← 状態（小さく）
│                             │
│  🇺🇸 英語 → 日本語           │
│  そのアバターめっちゃ         │
│  かわいいね、どこで買ったの？ │  ← 訳（大きく）
│                             │
│  Your avatar is so cute,    │
│  where did you get it?      │  ← 訳す前（小さく）
│                             │
│ [相手の声 ON]  [相手: 英語▼]  [⚙] │
└───────────────────────────┘
```

- 次の一言が来たら、まるごと入れ替える
- 翻訳中は、訳す前の文を先に出し、訳の場所に「…」を出す
- 日本語の声は、訳さずにそのまま大きく出す
- 「相手の声 ON/OFF」で、相手の声の翻訳を止められる（止めると PC も音を送らない）
- 「相手: 英語 / 中国語」で、自分の声を何語に訳すかを選ぶ

設定画面:

| 項目 | 初期値 | 意味 |
|---|---|---|
| Gemini の API キー | なし | 貼り付ける欄。保存後は末尾 4 文字だけ見せる。消すボタン |
| Gemini のモデル | `gemini-flash-latest` | |
| PC の IP アドレス | なし | 中継の `.exe` の画面に出る IP を入れる |
| 自分の声の翻訳に使うモデル | 1B | 1B / 4B |
| 相手の声の翻訳に使うモデル | 4B | 1B / 4B |
| 原文も出す（自分の声） | オン | |
| 自分の声の出し先 | KAT | KAT / チャットボックス / 両方（中国語は常にチャットボックス） |
| KAT の同期設定 | 8 | |
| 声の区切りの値 | Termux 版と同じ | しきい値、時間 |

### 自分の声

- アバターの「翻訳」トグル（`TranslatorActive`）がオンの間だけマイクを開く（Termux 版と同じ）
- 声の区切り、翻訳中の「...」、ページ分け、送り直し、オフにしたときの扱いは Termux 版の設計書と同じ。Python のコード（`Tools/translator/kat_osc.py`、`phone/display.py`、`phone/voice.py`）を C# に移す。テストも移す
- 出し先:

| 話した言語 | 訳 | KAT | チャットボックス |
|---|---|---|---|
| 日本語、相手が英語 | 英語 | 英訳 + `(かなの原文)` | 英訳 + `(原文)` |
| 日本語、相手が中国語 | 中国語 | 出さない（KAT は漢字を出せない） | 中文 + `(原文)` |
| 英語 | 日本語 | かなの訳 + `(英語の原文)` | 訳 + `(原文)` |
| 中国語 | 日本語 | かなの訳（原文は出さない） | 訳 + `(原文)` |

- KAT に出す日本語は、かなに直す。ローカル AI のときは、辞書で読みに変換する（形態素解析。例: NMeCab と IPADIC）。Gemini のときは、Termux 版と同じく Gemini に `kana` を返してもらう

### 相手の声

- 「相手の声 ON」の間、PC から届いた音（16 kHz、モノラル、16 ビット）を受け取り、自分の声と同じ方法で区切る
- 音声認識で言語も判定する。英語、中国語なら日本語に訳す。日本語ならそのまま。そのほか（韓国語など）や声でないものは出さない
- 画面にだけ出す。KAT、チャットボックスには送らない

### 音声認識

- **ローカル AI のとき: sherpa-onnx の SenseVoice（small）を、自分の声と相手の声の両方に使う。** 日本語、英語、中国語を自動で聞き分ける。ネットを使わない
  - Android に元から入っている音声認識は使わない。言語を 1 つに決めないといけない（自分が英語や中国語で話すと困る）、PC から届いた音を渡せない、R9 ではネットに送っている可能性がある、のため
  - R9 で動くか、速さは最初の作業で確かめる
- **Gemini のとき**: Termux 版と同じく、音声を 1 回送って、文字起こし、言語判定、翻訳をまとめて受け取る。返答の `lang` に `zh` を足し、訳す先の言語を指示文で伝える

### 翻訳（ローカル AI）

- LLMUnity で Gemma 3 1B と 4B（どちらも Q4_K_M）を読み込んでおく（合わせて約 3.5GB）
- 1 度に 1 件ずつ訳す。自分の声を先にする（周りの人を待たせないため）
- 指示文は短い例を添えて、訳だけを返させる。「もちろん、」などの前置き、引用符、ローマ字が付いたら取り除く
- 指示文の前半は毎回同じにし、読み込み済みの状態を使い回して速くする

### AI の切り替え

- `TranslatorLocalAI` がオン: ローカル AI（SenseVoice + Gemma）
- オフ: Gemini（自分の声も相手の声も）。キーがないときは、画面に「Gemini のキーがありません」と出し、ローカル AI で訳す
- 切り替えは次の声から効く

### モデルの用意

- アプリにはモデルを入れない（合わせて約 3.7GB）。初めて起動したときに Hugging Face から端末にダウンロードし、進み具合を出す。途中で切れたら続きから
- 開発中は `adb push` で入れてもよい

### PC の中継との通信

Termux 版の決まりを引き継ぐ:
- スマホ → PC 9002: KAT とチャットボックスの OSC、5 秒ごとの `/translator/hello`（起動ごとに変わる番号つき）
- PC → スマホ 9001: `TranslatorActive`、`TranslatorLocalAI`、`/avatar/change`
- 追加: hello に「相手の声 ON/OFF」を載せる。PC は ON のスマホにだけ、VRChat の音をスマホの 9003 番へ UDP で送る（20 ミリ秒ずつ、640 バイト。番号つき。欠けても止まらない）
- 最後の hello から 15 秒たったら、PC は音を送るのをやめる

### 記録

- アプリの保存場所に TSV で追記する: 日時、誰の声（自分 / 相手）、言語、原文、訳、使った AI
- 音声と API キーは記録しない
- 設定画面から記録ファイルを共有（ほかのアプリへ送る）できる

### API キーの扱い

- Android の端末内の保存場所（アプリだけが読める）に保存する
- 画面には末尾 4 文字だけ。ログ、記録、エラーの文に出さない
- 貼り付けたとき、英数字と `-` `_` 以外が入っていたら保存しない（Termux 版の `valid_key` と同じ）

### エラーのとき

- どのエラーでも止まらず、次の声を受け付ける（Termux 版と同じ）
- 自分の声の翻訳に失敗したら、KAT に `(error)` を 3 秒出す。相手の声なら画面に「訳せませんでした」
- 20 秒以上待った声は訳さずに捨てる（Termux 版のレビューの修正と同じ）
- 端末が熱くなって遅くなったときのために、1 件の翻訳が 15 秒を超えたら画面に「遅くなっています」と出す

## PC の中継（`translator_pc.exe`）

- C#（.NET 8）の 1 つの `.exe`。ダブルクリックで起動する。Python の `pc_osc_relay.py` の決まりをそのまま移す（テストも移す）
- **VRChat の音だけを取り出す**: Windows のプロセス ループバック録音で、`VRChat.exe` の音だけを録る。PC で流している音楽や動画は入らない。VRChat が起動していないときは待ち、起動したら録り始める
- 16 kHz、モノラルに変換して、相手の声 ON のスマホへ送る
- 画面に、自分の IP アドレス、スマホが見つかったか、音を送っているか、トグルの変化を出す
- 負荷は CPU 1〜2% 以内を目安にする

## 作る人の目線で読み直したあとの追記（2026-11-17）

### 利用者の答え

- **相手の声は、人の話し声だけを訳す。** VRChat の中の音（ワールドの BGM、効果音、動画プレイヤー）も PC から届くが、SenseVoice が音楽や効果音と判定したもの（イベントの印が BGM など）、話し声のないものは捨てる。動画の中の話し声は、人の声として訳されてもよい
- **BOOTH では無料で配る。** 使う部品とモデルは、無料での再配布・利用が許されるものにする。アプリはモデルを同梱せず、利用者の端末に、誰でもダウンロードできる場所（ログインの要らない Hugging Face のリポジトリ）から取ってくる。部品とモデルのライセンスを README と、アプリの設定画面の「ライセンス」に並べる
